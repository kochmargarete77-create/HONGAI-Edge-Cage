HONG AI｜MCP 授权对象隐私桥：研发预览

当前实现
受信宿主先授权一个具体文件并持有打开的文件句柄，模型只拿到随机对象 ID 和经批准的显示名称。
MCP 只暴露 read_object 与 propose_edit，不暴露真实路径、目录枚举、系统环境、网络查询、Shell、授权、解密或提交写入接口。
授权有到期与撤销机制；对象必须是普通文件，拒绝链接、目录、过大对象和未授权对象。修改只形成提案，由受信宿主后续提交，不擅自写客户文件。
路径映射可以用 AES-256-GCM 加密保存，并绑定隔离环境；密钥必须由沙箱外受信宿主保管，不能与密文一同交给 Claude 或其工具。
敏感环境字段可按宿主提供的字面值做输出脱敏；不是通用的秘密识别器，不能保证任意编码或业务文件中的所有身份信息都被识别。

必须说明的边界
这是可测试的核心库，不是已经接入官方 Claude Desktop 的完整 MCP 产品。当前不随客户端安装器自动启用，不要求客户安装 Node。
原生 Windows 与 macOS 的受信宿主、IPC 认证、密钥保管、进程权限和真实桌面 MCP 连接还需完成验证。
AES 加密解决静态路径映射保护；模型已经获准读取的正文仍然是正文，不能靠再加一层加密对接收服务隐藏。
如果仍允许一个不经此桥的全权限 Shell、MCP 或屏幕工具，就可能绕过对象边界；不能把桥的局部测试当成全桌面元数据绝对隔离。
下载文件和文件里的文字均为不可信数据，不能自行扩大授权或指挥宿主读取其他目录。

与当前客户问题的关系
优先修复探测误杀、登录数据持续性和更新路径。对象隐私桥用于减少工具的环境信息可见面，不是已确认“掉登录态”的根因修复证明。
本产品本轮不引入 Linux 或 Linux 客机。固定的本地环境 ID 用来保持配置连续，不等于伪造系统设备码或硬件指纹。
