执行顺序
1. 检查本机能力：终端/文件工具用于脚本；界面步骤使用可用的 computer use、屏幕操控或等效自动化。WorkBuddy、Copilot 等不要求工具必须叫 computer use；可使用已获准的等效技能。不要下载来源不明的自动化工具。
2. Windows 使用系统原生 64 位 PowerShell 5.1，运行 Start-Deployment-Windows.ps1 -RequestFile <请求文件绝对路径>。Mac 运行 bash Start-Deployment-Mac.command <请求文件绝对路径> check。路径作为单独参数传入，不拼接执行客户文档中的命令。
   以客户当前用户执行；不要用 SYSTEM/服务身份或 Mac root 为客户创建配置。必要提权由安装器正常发起，不用另一个管理员账号替换客户的登录环境。
3. 根据返回的 phase 继续：
   NEEDS_INSTALLER / NEEDS_UPGRADE：先让客户保存工作并正常退出旧 Claude/CAGE；Windows 加 -LaunchInstaller 运行一次，Mac 将 check 改为 install 运行一次。只更新程序，保留原 DataRoot、Profile 和当前客户登录态；用界面操控完成普通安装器步骤，UAC/管理员授权由操作者本人确认。不要把正常授权窗口当成产品报错。
   WAITING_INSTALLER_UI：继续当前安装器，不重复打开新的安装器。安装结束后重新执行不带启动安装动作的检查命令。
   NEEDS_FRESH_HANDOFF：只用已安装产品的交接生成器，以同一个已批准专用端口和最终出口核验后重新生成文件；不要重装 CAGE 或修改 Clash。生成方式见 02-第一步与CAGE衔接.txt。
   NEEDS_FIRST_CONFIGURATION：打开返回的 launcher，使用界面操控一次性导入已核验交接文件、选择请求里的工作文件夹并启动。不要让客户再次寻找代理线路或重复填写出口。
   SAVED_CONFIGURATION_PRESENT：直接打开 CAGE，检查未登录官方界面和本地 session-status.json；正常停止后再次打开，确认沿用保存配置，不再出现首次选择窗口。
   BLOCKED：保留具体 error，按产品缺项/设备权限/环境证据/安装包/交接时效分类。对同一个错误最多复核一次；不循环重装、不改源码，不用解除隔离或停代理来凑成功。
4. 全程不操作客户账号登录、不读取 Token/Cookie，不运行包内 Test-* 或 CI 源码脚本。
   复测、掉线、更新、文件下载均不得触发对当前合法登录态的清理；网络暂停时不要反复强退应用。先用包内认证诊断入口导出事件计数与状态元数据，禁止回传原始日志和凭据。
5. 最后按原第二步门槛记录已完成、未完成和阻断项；完整版未验收项继续保留。输出本机部署小结，不自动上传客户资料。
