HONG AI CAGE｜pilot.3 变更与复测
2026-11-26

已收录的缺陷：pilot.2 在 CI 中测试 MSIX 解包文件，却在客户环境直接启动 WindowsApps 中已注册包的 exe。二者启动条件不同，原测试不能证明客户的 MSIX 路径兼容。
客户的普通箱内程序与网络配置已通过，官方 exe 在装箱与不装箱的直接启动中均失败。该反馈按产品启动兼容缺陷处理，不再要求客户重做第一步网络整改。

Windows 新路径：
已注册、签名有效的官方 x64 MSIX → 读取官方 app 文件 → 建立本工具私有运行副本 → 逐文件 SHA256 校验与主程序签名验证 → 在专用隔离区启动。
原 MSIX 不卸载、不改文件、不修改 WindowsApps 所有权或权限，也不从执行别名在箱外代启动。
副本保留官方文件字节和签名，但不具有原 MSIX 包身份。通知、协议回调、自动更新、Cowork 等依赖包身份的能力不能据此宣称已通过；登录仍需客户在场验证。
第一次需额外空间存放官方运行文件，通常约 1 GB；之后复用缓存并检查完整性，不在安装器内重复携带官方本体。
官方包更新后按版本准备新副本；缓存异常或不兼容时停止，不能改成箱外运行或全局放行。

日常入口：
Mac 同时修复了图形宿主创建进程组后隔离助手 setsid 失败的问题；新增从真实安装工作台启动的回归测试，不能再以独立 CLI 启动代替。
第一次设置交接文件和工作文件夹。保存成功后，再双击 CAGE 直接核验并启动 Claude。
Windows：任务栏托盘中的 CAGE → 设置与运行状态 / 停止隔离会话 / 停止并退出。
Mac：菜单栏 CAGE → 设置与运行状态 / 停止隔离会话 / 停止并退出。
关闭设置窗口只隐藏设置；退出工作台或停止会话仍关闭本次受控进程。
出现错误才显示问题，已保存的参数不要求重复选择。

升级与复测：
1. 保留已通过的 Clash 专用入口、链式出口、DNS、TUN、远控和第一步恢复资料。
2. 先退出旧 CAGE 与 Claude，再覆盖安装新版本；不要停 Clash，不重启电脑。
3. 第一次启动观察官方运行副本是否准备完成、Claude 是否在指定隔离区出现。
4. 退出后再次双击，检查不再要求选择代理或目录，并核对 session-status.json 中的 runtimeCacheReused=true。
5. Windows 应记录 officialSourceKind=MSIX_PRIVATE_SIGNED_COPY 与逐文件校验数量；不再接受用 CI 原始解包 exe 覆盖生产发现路径的测试。
6. 第一轮只检查未登录启动与边界；真实登录、协议回调、聊天、MCP/扩展另列实际结果，不提前标 PASS。
7. 出现问题保留 session-status.json、版本、时间和错误；不修改系统网络来补救启动失败。

防火墙：
客户发现的“任意程序/任意协议/任意地址”放行不能用来解决启动兼容性。
第一步应核对规则真正的程序、包身份、协议、远端地址、方向与配置文件；记录规则来源和更新后的变化。
本包不恢复或新增全局任意放行。单纯按包 SID 限制网络只能算网络守卫，不能作为文件系统/进程沙箱通过的证据。

所有平台都从 HONG AI CAGE 入口启动才属于本工具声明的隔离会话。原系统 Claude 图标不计入该声明。
