HONG AI｜第一步与 CAGE 的衔接

第一步负责客户整机的网络配置与评分；第二步负责官方 Claude 桌面进程的隔离。
第二步安装器不得接管、重置或删除客户已有的 Clash、TUN、DNS、路由和远控配置。

推荐交接方式：单独为 CAGE 增加一个仅监听 127.0.0.1 的代理入口，直接绑定已验收的最终落地节点。
不要直接沿用可能按域名走 DIRECT 的通用混合端口。一次查询 IP 相同，不能证明其他请求也经过同一节点。

支持该功能的 mihomo 配置示意：
这只是向已有 listeners 追加一项，不能拿它覆盖完整配置；原有 listeners 也必须保留。

listeners:
  - name: HONGAI-CAGE-IN
    type: mixed
    listen: 127.0.0.1
    port: 17896
    proxy: HONGAI-FINAL-EXIT

17896 只是示例，必须检查端口未被占用。
HONGAI-FINAL-EXIT 必须替换为已有的具体落地节点名；该节点的 dialer-proxy 指向已配置的前置组。
禁止把 DIRECT、自动回落组或包含 DIRECT 的可选组作为此入口的出口。
此入口只用于 CAGE，原来的 mixed-port、规则、TUN 和远控链路保留。
不支持 listeners/proxy 的旧内核必须先明确兼容方案，不得静默退回通用端口。

操作顺序：
1. 备份当前有效配置，记录远控和智能体使用的原有端口。
2. 使用内核的配置校验功能验证修改；发现错误即停止，不加载错误配置。
3. 由现场操作者批准加载；只新增此入口，不修改全机 DNS、系统代理和路由。
4. 通过新入口连续核对三次最终 IPv4，并交叉检查 Clash 实际连接链。
5. 生成 clash-handoff.json，十分钟内导入 CAGE。
6. 首次启动只打开官方桌面程序，不登录；确认签名、入口和进程归属。
7. 客户在场时验收登录、会话与所需工具，再决定是否交付。

CAGE 启动后会使用私有的会话端口，因此第一步如果有“Claude 只能访问旧混合端口”的进程防火墙规则，必须先检查冲突。
不得删除未知防火墙规则，也不能为了通过测试开放 Claude 任意出网。

目标路径：官方桌面进程/受控子进程 → CAGE 私有入口 → Clash 专用入口 → 前置节点 → 最终落地。
入口或代理停止后，只影响本次隔离会话；不修复为 DIRECT，不更换出口，不重启整机。
IP 定时核验不是每条业务连接的出口证明，交付时仍需检查专用入口的实际绑定与连接链。
