HONG AI CAGE｜pilot.5 / Mac build 10 变更与边界

本轮已实现的产品改动
1. 重复启动先取得会话所有权，失败不覆盖正在运行的状态；状态文件原子更新。
2. 会话探测与应用存活分开：失败先关闭网关和已有隧道，程序与现有资料保留；恢复原入口并连续核验三次后才放行。
3. 健康核验降低频率，两个独立回显服务仅经同一批准代理查询；单个服务故障可换检测服务，不更换代理。有效出口不一致立即阻断，不能用另一结果掩盖。
4. 增加本地固定环境 ID，重开和版本升级沿用；不生成或伪造硬件设备码，不读取硬件序列号。
5. Windows 桌面快捷方式清空旧参数，图标来自官方程序完整应用图标资源；Mac 使用官方应用 ICNS。名称仍保留 HONG AI CAGE，避免把普通 Claude 入口误认为受保护入口。
6. 缓存的官方运行文件只读，更新后的进程和子进程继续受同一边界约束。版本/签名/边界不兼容时停止，不转到原版图标、不清 Profile 凑启动成功。
7. 增加只输出状态、存储元数据与错误计数的认证诊断；不导出 Cookie/Token、原始日志或真实路径。日志仅在本机受信诊断过程中作有界检查。
8. 第一包 H04 保留权重和硬门槛，明确当前合法专用登录态不属于待清理旧残留。复测、掉线、下载、更新、关机后不能自动清理登录数据。

诊断入口
Windows：在已安装目录使用 Collect-AuthDiagnostics.ps1 -DataRoot <已安装数据目录>。默认只输出 JSON；需要保存时指定一个尚不存在、文件名为 auth-diagnostics.json 的数据盘路径。
Mac：运行已安装应用 Contents/MacOS/HongAICage --auth-diagnostics；保存 stdout 到获准的服务目录。
统计结果用于分辨认证、存储、网络、身份回调和明确账号提示，不能凭某个关键词计数直接认定封号或根因。

日志结论修正
已收到客户的 Windows 登录成功与运行稳定报告，同时也收到掉登录态反馈；这些属于客户报告，不能推广为所有设备/功能已验收。
零非回环连接能支持观测窗口内的连接路径结论，不能证明加密正文没有本地信息。没有观察到 UDP 也不能证明系统 DNS 服务从未代查询。
登录前引导页后来可显示，且客户报告 OAuth 成功，所以不能把白屏一概定因为“没有 MSIX 身份”；包身份丢失仍是确实存在的功能风险，要按具体功能与错误验证。
不得为安装本工具关闭 Smart App Control、WDAC、Defender、Gatekeeper 或 SIP。权限/签名问题应由正常发布与授权机制解决，不让客户承担不可逆的安全设置变化。

尚未实现的保护
对象化 MCP 已有核心原型，支持随机对象 ID、文件句柄授权、映射 AES-GCM 加密、输出脱敏、撤销和修改提案；尚未完成官方桌面端、可信 IPC 和密钥保管集成，不随本版自动启用。
当前轻量进程沙箱不能宣称所有系统 API、硬件标识、时区、设备信息或任意工具输出均不可见。全权限外部工具也可能绕过对象桥；不能同时放任其访问宿主并宣称周边环境不可见。
本产品本轮不引入 Linux 或 Linux 客机。真实 Windows/macOS 硬件虚拟化是不同的系统方案，本地环境 ID 不替代它。
固定出口、沙箱、加密或环境评分都不保证账号不会退出或被限制；本地清理也不能修复服务端撤销。

独立验收要求
第一步与自动环境评分继续不代办登录。客户本人登录后，另行观察聊天、下载、正常重开、代理暂停恢复、闲置刷新、更新与正常关机后的保持。
只在自有测试机或客户正常操作时观察开关机，不在单远控服务中强制重启。实际认证连续性未完成时，F15 仍 NOT_ACCEPTED。
