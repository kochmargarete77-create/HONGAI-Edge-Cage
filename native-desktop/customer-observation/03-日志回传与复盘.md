# HONG AI｜日志回传与复盘

客户回传内容仅限观察器新建的 session 目录，以及可选的事件标记文件。不要直接导出官方客户端或代理的原始日志，不要添加截图、账号信息、历史配置和业务文件。

服务方在项目目录使用已有 Python 运行：

```text
python analyse_observation.py --input <session中observation.ndjson的绝对路径> --output <专用项目目录下尚不存在的analysis.json绝对路径>
```

两个路径都必须具体指定；输出文件不能已存在。Windows 输出在 D/E，macOS 使用批准的普通项目目录。分析器不发请求、不修改原日志，也不复制未知字段到报告。原始输入必须来自本包观察器，分析器不会为任意第三方日志出具隐私认证。

## 复盘顺序

1. **先验证记录本身。** 检查 session、采样顺序、footer、样本数量和采集状态；截断、权限不足、记录冲突和中断分别标明。
2. **再核对时间线。** 比较 UTC 和单调耗时，检查采样空窗、进程角色变化和客户标记事件。正常时钟校正和进程数量变化不自动当作环境矛盾。
3. **只提出证据支持的线索。** 例如应用角色可见而代理名称角色不可见，表示需要核查；不能直接认定直连、网络泄露、遥测回传或封号原因。
4. **列清楚没看到的部分。** HTTPS 请求正文、所有短连接、完整 MCP 调用、实际设备采集、软件指纹和登录状态均不由这些计数建立覆盖。
5. **形成下一轮具体检查。** 使用固定问题与时间窗口，优先查可复现的稳定性、兼容与错误处理问题；不要因为猜测而改网络或清登录态。

## 一致性闭环的判据

同一观察窗口内，已确认事实应当跨模型、系统、应用、持久状态和工具结果相互支持；正常差异应有解释和证据。整体闭环优先于单项分数，但核心路径的真实矛盾不能用其他高分抵消。尚未观测的板块保持未知，不算合格，也不凭空判为不合格。

本包仅增加“可见进程角色与连接元数据”的客户侧证据。它可以缩小排查范围，不能变相完成未实施的官方读取适配或物理硬件仿真。
