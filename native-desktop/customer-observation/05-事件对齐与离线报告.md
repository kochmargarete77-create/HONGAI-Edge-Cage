# HONG AI｜事件对齐与离线反馈

本功能把已经生成的观测日志、客户事件标记和可选的其他会话合并为一份诊断报告。不再采集本机信息，不修改代理或登录状态，不联网回传。

## 一条命令生成报告

使用已有 Python，具体指定真实绝对路径：

```text
python feedback_report.py --log <observation.ndjson绝对路径> --output-parent <已批准项目目录的绝对路径>
```

有事件标记时增加 `--events <事件JSON绝对路径>`。需要比较另一份记录时增加 `--compare-log <另一份NDJSON绝对路径>`，最多八份输入。默认视作独立会话；只有操作者明确声明同一工单时才使用 `--comparison-scope same_case_operator_declared`，这个声明不确认同设备或同账号。

输出在新的 `report-随机编号` 子目录，包含 `analysis.json`、`report.html`、`manifest.json`。不覆盖旧报告，不复制原始日志、业务内容或路径；每份输入只读一次，同一字节快照用于分析与对齐，并记录 SHA-256。报告为本地静态 HTML，无脚本、外链字体、图片或追踪请求。Windows 输出使用 D/E 的专用项目目录；没有已有 Python 时交由服务方分析，不临时安装。

## 事件标记的准确格式

保持模板中的 `events` 为空，直到有真实的客户报告或界面观察。下面仅演示格式，不表示已经发生过该操作，不要把示例作为客户事件回传：

```json
{
  "utcISO": "2026-11-28T00:00:05.000Z",
  "kind": "download",
  "source": "customer_reported",
  "result": "completed",
  "code": "NONE"
}
```

五个字段必填，枚举取值见 `02-事件记录模板.json`。只有知道观察器的单调时钟基线时才额外填写 `elapsedSeconds`；否则省略，不用 UTC 差值补造它。不得增加自由备注、任务标题、文件名、账号、地址或正文。模板的 `sessionId` 必须换成对应观察器给出的随机编号。

## 对齐与比较如何解释

- UTC 与相对耗时分别核对。事件越窗、发生在最早样本之前、时钟信息相悖或记录不完整时，保留原时间并标记未对齐，不强行绑定样本。
- 时钟精度容差为一秒，报告明确保留差值。附近样本的搜索半径不超过三十秒，最多两个；这只是时间相邻，不证明因果。
- 重复日志、重复会话和混合的合成／客户观测来源不作为多次验证。合成样例在报告顶部明确标记。
- 多次采集仅比较可见覆盖、缺失、记录问题和线索数量。数量减少不表示封号风险下降；窗口不同、设备相同与否、账号相同与否仍需独立证据。

报告不出环境合格分数，不认证来源，也不把未观测的硬件、软件指纹、全请求链或账号状态补成已通过。原有第一步评分文件与规则保持原样。
