# HONG AI｜客户端只读观测包

本包用于正常使用中的稳定性诊断与问题复盘。它不配置网络、不读取账号会话、不实现设备身份模拟，也不修改官方程序。

## 交给客户智能体

1. 将本文件夹或完整 ZIP 交给客户电脑的智能体，发送 `01-客户智能体只读观测指令.md` 的全文。
2. 智能体先确认系统与已有执行工具，再按相应 README 运行观察器，默认 5 分钟，每 10 秒采样。
3. 客户保持原来已登录的应用与网络，按自己的需要正常使用。不要为了采集刻意登录、退出、切节点、重启应用或发送测试对话。
4. 结束后只回传观察器新建的 `session-随机编号` 目录。智能体可补一份按模板填写的事件记录；不收集聊天、文件正文或任务内容。
5. 服务方使用 `analyse_observation.py` 生成诊断摘要，结合实际问题复盘。原始应用配置、账号资料与未脱敏日志不得混入回传包。

需要完整离线反馈时，使用 `feedback_report.py`：统一生成 JSON、HTML 和校验清单，支持事件时间对齐与多次会话元数据对比。具体命令见 `05-事件对齐与离线报告.md`。报告保留缺测与来源声明，不把相关性当成因果。

## 实际能够看到什么

- 按固定名称识别的应用、代理与远控进程角色数量、CPU 和内存聚合。这是名称线索，不是官方签名身份验证。
- 当时可见的 Claude 进程 TCP 状态、IPv4/IPv6、目标端口类别和远端地址类别计数。原始 PID、地址和执行路径只在采集器内存中用于匹配，不保存或导出。
- UTC 时间线、单调时钟耗时、权限或接口不可用的固定状态。

这不是 HTTP 请求抓包，不能看到加密业务正文、所有短连接、全部后台请求或完整 MCP 调用。零条连接只代表那个采样瞬间未看到匹配连接。

## 账号与网络保持原状

不读取密码、Cookie、Token、聊天正文、登录数据库、设备序列号或 MAC 地址；不修改 Clash、TUN、DNS、路由、防火墙、Wi-Fi、时区或认证资料。不请求提权，不安装依赖、证书、驱动或扩展，不抓包、解密 TLS、注入程序、开放调试端口或停止现有进程。缺权限记录 `NOT_OBSERVED`，不通过改系统来补齐。

默认 5 分钟，最长配置窗口 30 分钟、最多 180 次采样、输出总量上限 5 MiB。Windows 系统查询若延迟，返回时间可能晚于窗口；这不是硬性墙钟保证。只新建自己的随机目录和文件，遇限制停止记录，不删除客户文件。只退出观察器即可结束采集，客户端和代理不随之退出。

采集器带来的 CPU/磁盘开销是有限的，但无法承诺对任意机器或其他软件完全零影响。检测到明显负载异常时停止观察器，保留已生成记录；不通过重启客户电脑来验收。

## 怎么判断整套一致性

整体闭环需要模型、实际读取、持久状态、工具结果和正常业务行为共同支持。已有模型测试通过，不等于客户真实硬件读取已被覆盖。客户日志可揭示矛盾、生命周期变化和缺测窗口，不能补造没看到的证据。

分析结果分为事实、待排查线索与未观测项。不用“聊天后出现错误”的先后顺序推定封号原因，不凭 TCP 类别判断直连泄露，不把任何单个分数当作账号安全保证。本包不签发环境合格证或自动修改原有评分。
