# HONG AI Edge Cage 受控领取与部署协议

## 公开仓库与受控交付的边界

公开 GitHub 仓库中的明文内容可以被匿名克隆、缓存和分叉，无法通过应用层密钥阻止，也无法让 HONG AI 获得每个匿名下载者的身份。因此正式架构把两类内容分开：

1. **公开 AGPL 核心**：跨平台沙箱控制器、通用安全协议、构建说明和安全修复。
2. **加密交付包**：签名后的客户安装包、企业策略包、品牌资源和客户配置，只以加密文件形式放在 GitHub Release。
3. **HONG AI 授权服务**：验证长期授权密钥与一次性令牌，记录密钥签发事件，并把该版本的内容密钥重新包裹给本次安装的临时公钥。

记录的是每次“授权解锁、安装开始和安装完成”，不是 GitHub 无法可靠提供身份的匿名文件下载。

## 激活协议

1. 客户安装器在内存中生成一对 X25519 安装密钥和随机 `installId`，不采集硬件序列号作为身份。
2. 操作人员输入长期授权密钥与一次性临时令牌。二者不得出现在命令行、日志、GitHub Actions 输出或截图中。
3. 安装器向授权服务提交授权材料的 TLS 请求、`installId`、临时公钥和目标 `artifactId`。
4. 授权服务验证长期密钥、令牌有效期、单次使用状态、客户和允许版本。
5. 授权服务记录脱敏事件，将 32 字节发布内容密钥用客户临时 X25519 公钥重新包裹，并用 HONG AI Ed25519 发布签名私钥签名。
6. 安装器使用内置的 HONG AI 签名公钥验证信封，核对 `artifactId`、`installId` 和五分钟有效期。
7. 安装器从公开 GitHub Release 下载 AES-256-GCM 加密包，校验哈希并在 D/E 盘产品临时目录解密。
8. 客户端验证源码包结构，拒绝路径穿越与链接条目，只调用仓库内固定平台安装脚本；成功后上传 `INSTALLED` 回执，失败上传 `FAILED`。
9. 默认安全清除临时明文压缩包；授权安装目录、客户状态和恢复包保留在指定数据盘。

本仓库同时提供授权服务和交互式领取客户端的参考实现。生产操作命令、TLS 边界和密钥备份要求见 `LICENSE-SERVICE.md`。

## 服务端必须记录

- 事件 ID、客户/许可证内部 ID、制品 ID和版本。
- 请求、批准、下载确认、安装完成或失败的时间。
- 随机安装 ID 的哈希，不记录主板、磁盘或网卡序列号。
- 一次性令牌状态、结果代码和前一事件哈希。
- 必要的安全审计网络信息，按客户合同设定保留期并脱敏。

严禁记录许可证明文、一次性令牌明文、代理账号密码、Cookie、OAuth Token、Claude 登录态或解密后的发布内容密钥。

## 防复制能力的真实边界

加密交付能阻止未授权者直接使用公开 Release 文件，也能追踪合法密钥的签发与安装。但任何在客户管理员权限下解密并执行的软件，都无法保证永远不被提取。进一步保护知识产品应依靠分层：公开核心、服务端策略计算、按客户水印的签名制品、合同与审计，而不是宣称客户端代码绝对不可复制。
